# Nu, Pogodi! — Wolf and Eggs

A portrait HTML5 game in the spirit of the classic pocket electronic game. Four hens lay eggs down four colored chutes. Move the wolf so the basket is waiting when an egg arrives. Three penalty points end the run.

The pictures, sounds and code in this repository are original. They are not extracted from the cartoon or from the original toy.

## Rules

- Catching an egg scores one point. Each egg is scored once.
- A miss with the hare hidden adds one penalty point. The penalty chicks are solid.
- A miss while the hare is looking out of the window adds half a penalty point. The newest chick blinks, the egg breaks, and a chick runs off.
- Penalties are stored as half-points, so the counter can show 0, 0.5, 1, 1.5, 2, 2.5 and 3 without floating-point drift.
- Three penalty points end the game. Spawning stops, and the score no longer changes until the next run.
- Eggs start slowly. Speed rises with every point, dips a little at each hundred, and never falls all the way back to the opening pace.
- At 999 the next catch shows 000. The record stays 999, penalties are kept, and speed drops slightly while remaining much faster than a new game.
- Penalties clear once when the displayed score crosses 200, and once when it crosses 500. The same thresholds work again on later cycles. Rolling past 999 does not clear them.
- **Game A** uses three chutes. The closed chute depends on the penalties:

  | Penalties | Closed chute |
  | --- | --- |
  | 0 | Lower left |
  | 0.5 and 1 | Lower right |
  | 1.5 and 2 | Upper left |
  | 2.5 | Upper right |

  Eggs already on a chute finish their run when the pattern changes. New eggs are not sent down a chute that is closing.
- **Game B** uses all four chutes.
- Starting either mode begins a new run. The saved record is kept. Only one animation loop is active.
- Pause freezes eggs, spawning and the hare. Hiding the browser tab pauses the run as well, so time spent in the background is not simulated.
- The record is stored in the browser, capped at 999. Hold **GAME A** or **GAME B** to highlight it. A short tap starts that mode.

Hare timing is configurable in `src/game/config.ts`. It is a playable cycle, not a historical measurement of the original device.

## Stack

- TypeScript
- Canvas 2D
- Vite
- A small service worker generated by `vite-plugin-pwa`
- Vitest for the rules, without a browser

There is no account, no analytics, and no required network service. The Android build is a PWA, not a native APK.

## Requirements

- Node.js 22 (Node 20 or newer should also work)
- A current Android Chrome, or any current desktop browser, for play

## Local play

```bash
npm install
npm run dev
```

Open [http://localhost:5173/Game-Nu-pogodi/](http://localhost:5173/Game-Nu-pogodi/).

The `/Game-Nu-pogodi/` prefix matches the GitHub Pages project URL, so local play and the published build use the same paths.

The picture is a wide pocket toy: silver case, green LCD, four red buttons and side switches.

## File for a phone

```bash
npm run phone
```

This writes `release/wolf-catches-eggs.html`. Copy that single file to the phone and open it in Chrome. Details are in `INSTRUCTIONS.ru.md`.

## Production build

```bash
npm test
npm run build
npm run verify:dist
npm run preview
```

Preview serves the built game at [http://127.0.0.1:4173/Game-Nu-pogodi/](http://127.0.0.1:4173/Game-Nu-pogodi/).

## Tests

```bash
npm test
```

The suite covers scoring, one-time resolution of an egg, full and half penalties, game over, the 200 and 500 clears, both modes, the 999 rollover, pause, the frame-time cap, the saved record, and layout on narrow and landscape viewports.

`npm run test:smoke` launches the production build in headless Chrome (mobile viewport, pause, rotation, offline reload). It needs Google Chrome and a completed `npm run build`.

## Controls

| Action | Touch | Keyboard |
| --- | --- | --- |
| Upper left | UL | Q, 1 |
| Upper right | UR | W, 2 |
| Lower left | LL | A, 3 |
| Lower right | LR | S, 4 |
| Pause | PAUSE | P, Esc, Space |
| Sound | SOUND | M |
| Vibration | BUZZ | H |
| New run | GAME A or GAME B | — |

The wolf's basket changes lane as soon as you press. The drawing eases across; catching does not wait for the drawing. On a touch screen you can also slide between the four lane buttons.

## Install on Android

1. Publish the site, or open the preview over HTTPS or localhost.
2. In Chrome, open the menu and choose **Install app** or **Add to Home screen**.
3. Launch **Wolf & Eggs** from the home screen. The manifest asks for a standalone / fullscreen window.
4. The first online visit caches the app. After that, airplane mode can still open the installed game.

Sound starts after the first tap, because mobile browsers block audio that plays by itself. Vibration can be turned off with **BUZZ**. Some browsers only allow vibration inside the tap that requested it, so a buzz on a later catch is best-effort.

## GitHub Pages

The workflow in `.github/workflows/pages.yml` runs the tests and the production build on pull requests. On a push to `main` it also deploys `dist/` with GitHub Pages.

One-time repository setting: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

The site is served from `/Game-Nu-pogodi/`, which is the `base` in `vite.config.ts`. Asset URLs are not hard-coded to the domain root.

## Offline

The service worker precaches the HTML, script, stylesheet, manifest and icons. Nothing is loaded from a CDN. After the first successful visit, the game starts without a network connection. A later deploy updates the cache when the new service worker activates (`autoUpdate`).

## Tuning

Speed, spawn spacing, hare timing, penalty size and animation lengths live in `src/game/config.ts`.

## Native APK

This repository does not build an Android APK. The environment used to create the project has no Android SDK, and a Capacitor or Gradle project would not be something this tree can compile. Install the PWA instead. A store package can later be wrapped from the same Pages URL with a tool such as Bubblewrap, without changing the game rules.

## Limitations

- Portrait play is the intended layout. Landscape keeps the same board, letterboxed, so the buttons get smaller.
- The record is local to one browser profile.
- Hare intervals are not claimed to match the original hardware.
- Haptic feedback depends on the browser.
- This project was not tested on a physical Android phone in the implementation environment. Logic tests and a headless Chrome mobile viewport were used instead.
